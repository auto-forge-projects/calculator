# DL-05-001: Elle tokenize/parse + sabit operatör tablosu (eval yasağı) & sıfır-dep test

- Tarih: 2026-07-24
- Faz: 5 — Mimari Tasarım
- Mod: AUTOPILOT
- Karar: Hesap mantığı, kullanıcı girdisini `parseNumber()` ile yalnızca sayıya çeviren + işlemi
  SABİT bir operatör tablosundan (allowlist: `+ - × ÷`) seçen saf fonksiyonlar olarak tasarlanır.
  `eval()`/`Function()`/`new Function()` mimari düzeyde YASAKTIR (repoda hiç bulunmaz). Hatalar
  istisna yerine `{error}` birliğiyle taşınır (çökmez). Testler bağımlılık eklemeden Node yerleşik
  test runner'ı (`node --test`) ile saf fonksiyonlar üzerinde koşar.
- Değerlendirilen alternatifler: (1) `eval(`${a}${op}${b}`)` ile ifade değerlendirme — reddedildi
  (NFR-2 ihlali, kod enjeksiyonu yüzeyi). (2) Jest/Vitest test aracı — reddedildi (LITE'ta sıfır-dep
  hedefini bozar; 4-işlem için gereksiz araç). (3) İstisna fırlatıp `try/catch` — kabul edilebilir
  ama `{error}` birliği hata yolunu tip düzeyinde görünür/test edilebilir kılar, tercih edildi.
- Gerekçe: NFR-2 (eval yasağı) en güvenli biçimde allowlist operatör tablosuyla karşılanır — girdi
  hiçbir zaman kod olarak yorumlanmaz; kod incelemesi `grep eval` kadar basit. Saf fonksiyonlar
  NFR-3 için doğrudan birim test edilebilir. Node yerleşik runner Faz 4 sıfır-bağımlılık kararını korur.
- Riskler: (a) Elle parse edge-case'leri (bilimsel notasyon, virgül/nokta ondalık, taşma) kaçırabilir
  → FR-5 hata yolları + `app.test.js` senaryolarıyla izlenir. (b) `node --test` sürüm gereksinimi
  (Node ≥18) → README'de belirtilecek. Düşük etkili.
- Geri alınabilirlik: Yüksek (parser saf fonksiyon olduğu için mantık değişmeden test aracı veya
  UI katmanı değiştirilebilir; framework/eval kilidi yok, bağımlılık kilidi yok).
